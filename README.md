# SRTgo Plus: K-Train (KTX, SRT) Reservation Assistant

> [!NOTE]
> 원본 [srtgo](https://github.com/lapis42/srtgo) 프로젝트가 2025년 9월 개발 중단됨에 따라, 본 저장소에서 이어서 유지보수 및 개발을 진행하고 있습니다.
> 코레일(KTX)의 anti-bot 정책 변경에 대응하여 정상 동작하도록 수정하였습니다.

> [!WARNING]
> 본 프로그램의 모든 상업적, 영리적 이용을 엄격히 금지합니다. 개인적인 승차권 예매 용도로만 사용해 주세요. 본 프로그램 사용에 따른 민형사상 책임을 포함한 모든 책임은 사용자에게 있으며, 개발자는 어떠한 책임도 부담하지 않습니다. 본 프로그램을 내려받음으로써 위 사항에 동의하는 것으로 간주됩니다.

## 설치

```bash
pip install git+https://github.com/DionNam/srtgo_plus.git
```

## 사용법

터미널에서 아래 명령어를 실행하면 됩니다.

```bash
srtgo
```

### 1. 로그인 설정

처음 사용 시 **로그인 설정**에서 SRT 또는 KTX 계정을 등록합니다.

- 멤버십 번호, 이메일, 전화번호 중 하나로 로그인 가능
- 로그인 정보는 시스템 키체인에 안전하게 저장됩니다

### 2. 예매 시작

1. **SRT** 또는 **KTX** 선택
2. 출발역, 도착역, 날짜, 시간, 승객수 선택
3. 검색된 열차 목록에서 원하는 열차 선택 (복수 선택 가능)
4. 좌석 유형 선택 (일반실 우선 / 일반실만 / 특실 우선 / 특실만)
5. 매진 시 자동으로 빈 자리가 날 때까지 재시도

### 3. 텔레그램 알림 (선택)

텔레그램 봇을 연동하면 예매 성공 시 알림을 받을 수 있습니다.

1. [@BotFather](https://t.me/BotFather)에서 봇 생성 후 토큰 발급
2. **텔레그램 설정** 메뉴에서 토큰과 chat_id 입력

### 4. 카드 결제 (선택)

카드 정보를 미리 등록하면 예매와 동시에 자동 결제가 가능합니다.

## 자동 감시/예매 (srtgo-watch)

`srtgo` 의 예매 시작은 대화형이라 열차를 손으로 고르고 터미널을 붙잡고 있어야 하며, 하루치만
다룹니다. `srtgo-watch` 는 **"23일 오후 ~ 24일 오전" 처럼 날짜를 넘는 시간 구간**을 통째로
감시하는 비대화형 명령입니다. 기본은 알림만 주고, `--reserve` 를 주면 예약까지 진행합니다.

```bash
# 9/23 12:00 ~ 9/24 12:00 사이 서울 → 포항 KTX 를 60초마다 확인
srtgo-watch --rail KTX --dep 서울 --arr 포항 \
    --start "2026-09-23 12:00" --end "2026-09-24 12:00" \
    --interval 60 --telegram
```

```bash
# 수서발 SRT 도 같이 보기 (SRT 는 서울역에 서지 않으므로 자동으로 수서로 바뀝니다)
srtgo-watch --rail KTX --rail SRT --dep 서울 --arr 포항 \
    --start "09-23 12:00" --end "09-24 12:00" --include-standby
```

```bash
# cron 용: 한 번만 확인하고 종료
*/5 * * * * srtgo-watch --dep 서울 --arr 포항 --start "09-23 12:00" --end "09-24 12:00" --once --telegram
```

### 주요 옵션

| 옵션 | 설명 |
| --- | --- |
| `--rail KTX\|SRT` | 감시할 철도사. 여러 번 지정 가능 |
| `--dep` / `--arr` | 출발역 / 도착역. `--dep` 는 여러 번 지정 가능 (예: `--dep 서울 --dep 수서`) |
| `--srt-dep` / `--srt-arr` | SRT 쪽 역만 따로 지정 (기본은 `--dep`/`--arr`, 수도권이면 수서로 대체) |
| `--start` / `--end` | 감시할 **출발 시각** 범위. `"2026-09-23 12:00"`, `"09-23 12:00"`, `"23 14"` 모두 가능 |
| `--passengers` | 성인 승객 수 (기본 1) |
| `--seat-type any\|general\|special` | 어떤 좌석이 열릴 때 알릴지 |
| `--include-standby` | 예약대기 신청 가능도 '자리 있음' 으로 간주 |
| `--ktx-only` | KTX 등급만 조회 (무궁화·ITX 제외) |
| `--interval` | 조회 간격(초). 최소 10초, 실제로는 약간의 지터가 붙습니다 |
| `--once` | 1회만 확인하고 종료 (cron 용) |
| `--telegram` | 텔레그램으로 알림 전송 |
| `--exec "명령"` | 자리가 났을 때 실행할 셸 명령. 알림 내용이 `$SRTGO_MESSAGE` 로 전달됩니다 |
| `--repeat-notify N` | 자리가 계속 남아 있으면 N분마다 재알림 (기본 0 = 상태가 바뀔 때만) |
| `--reserve` | 자리가 나면 즉시 예약까지 진행 |
| `--pay` | 예약 성공 시 등록된 카드로 결제 (`--reserve` 필요) |
| `--prefer earliest\|latest` | 동시에 여러 편이 열렸을 때 잡을 순서 |
| `--dry-run` | 예약 직전까지만 수행 (`--reserve` 검증용) |
| `--yes` | 자동 예매 확인 프롬프트 생략 (비대화형 환경에서 필수) |
| `--child` / `--senior` | 어린이 / 경로 승객 수 |

알림은 **매진 → 예매가능 으로 바뀌는 순간에만** 나가므로 같은 열차로 반복해서 울리지 않습니다.
다시 매진됐다가 또 풀리면 그때 한 번 더 알립니다.

### 자동 예매 (`--reserve`)

```bash
# 구간 안에서 가장 빠른 열차로 자동 예약 (결제는 직접)
srtgo-watch --rail KTX --rail SRT --dep 서울 --arr 포항 \
    --start "2026-09-23 12:00" --end "2026-09-24 12:00" \
    --reserve --passengers 2 --telegram
```

- 조건에 맞는 자리를 발견하면 **즉시 예약**하고, 성공하면 알림을 보낸 뒤 종료합니다.
- 동시에 여러 편이 열렸으면 `--prefer earliest`(기본) / `latest` 순서로 시도하고,
  한발 늦어 매진되면 자동으로 다음 후보를 시도합니다.
- `--pay` 를 주면 `srtgo` 의 **카드 설정**에 등록된 카드로 결제까지 진행합니다.
  예약대기(`--include-standby`)로 잡힌 건은 결제 대상이 아니므로 건너뜁니다.
- 결제를 걸지 않았다면 **구입기한 내에 직접 결제해야** 예약이 취소되지 않습니다.

> [!WARNING]
> `--reserve` 는 실제로 예약을, `--pay` 는 실제로 결제를 일으킵니다. 시작 전에 조건을 보여주고
> 확인을 받으며, 터미널이 아닌 환경(cron·systemd 등)에서는 `--yes` 를 명시해야 실행됩니다.
> 조건이 맞는지 먼저 확인하려면 `--dry-run` 으로 돌려보세요. 예약 직전까지만 수행합니다.

```bash
# 어떤 열차를 잡게 될지 먼저 확인 (실제 예약 없음)
srtgo-watch --dep 서울 --arr 포항 --start "09-23 12:00" --end "09-24 12:00" \
    --reserve --dry-run --once
```

### 로그인 정보

`srtgo` 의 **로그인 설정**으로 저장한 키체인 값을 그대로 씁니다. 키체인이 없는 서버라면
환경변수로 줄 수 있습니다.

```bash
export KTX_ID=... KTX_PASS=...
export SRT_ID=... SRT_PASS=...
export TELEGRAM_TOKEN=... TELEGRAM_CHAT_ID=...   # --telegram 사용 시
```

> [!IMPORTANT]
> **KTX·SRT 통합(2026-09-01 운행분~) 이후 수서 출발 편성도 코레일이 판매합니다.**
> 수서발 열차는 SR API 로도 조회는 되지만 예약 단계에서
> "요구하신 열차는 예약이 불가능한 열차입니다" 로 거부됩니다.
> 따라서 수서발을 노릴 때도 `--rail KTX` 를 쓰고 출발역만 추가하세요:
> `--rail KTX --dep 서울 --dep 수서`. 같은 철도사 감시자끼리는 세션을 공유하므로
> 로그인은 계정당 한 번만 일어납니다.

## 일행 좌석 모으기 (srtgo-pair)

명절처럼 **2석이 한 번에 나오지 않는** 상황을 위한 명령입니다. `srtgo-watch` 가
"조건에 맞는 자리 하나"를 노린다면, `srtgo-pair` 는 **1석씩 사 모아서 한 열차에
인원수를 맞추는** 전략을 씁니다.

```bash
srtgo-pair --dep 서울 --dep 수서 --prefer-dep 수서 --arr 포항 \
    --start "2026-09-23 17:00" --end "2026-09-24 10:00" --seats 2
```

동작 방식:

1. 구간 안의 모든 열차를 훑으면서 **1석이라도 열리면 일단 예약**합니다.
   여러 열차에 1장짜리 예약이 흩어져 쌓이는 게 정상입니다.
2. 어느 한 열차에 예약이 `--seats` 만큼 겹치는 순간이 목표 달성입니다.
3. `--prefer-dep` 을 주면 2단계로 동작합니다. 달성한 열차가 `--prefer-dep` 출발이면
   종료하고, 아니면 그 표를 **바닥으로 깔아둔 채** `--prefer-dep` 출발 열차만
   대상으로 같은 일을 반복합니다. 이미 잡은 표는 절대 놓지 않습니다.

우선순위는 ① 이미 표를 들고 있는 열차(짝이 맞으므로) ② `--prefer-dep` 출발
③ 이른 출발 순입니다.

### 예약대기 (`--include-standby`)

매진이어도 **예약대기**가 열려 있는 열차가 있습니다. 걸어두면 나중에 자리가 풀릴 때
유리하므로, 좌석 탐색과 병행해 대기를 깔아둘 수 있습니다.

```bash
srtgo-pair --dep 서울 --dep 수서 --prefer-dep 수서 --arr 포항 \
    --start "2026-09-23 16:00" --end "2026-09-24 09:00" \
    --seats 2 --include-standby --max-standby 2
```

- **예약대기는 좌석으로 세지 않습니다.** 대기만 쌓였다고 목표를 달성한 것으로 보고
  종료하는 일은 없습니다. 좌석 탐색은 그대로 계속됩니다.
- **목표는 언제나 한 열차에 `--seats` 석입니다.** 1석짜리 대기 하나로 끝내지 않고,
  이미 가진 좌석과 걸어둔 대기를 합쳐 인원수가 찰 때까지 채웁니다. 인원수 대로
  먼저 신청하고, 거부되면 1석씩으로 물러서서 같은 열차를 계속 채웁니다.
- 이미 좌석이나 대기가 걸쳐 있는 열차를 **최우선**으로 채웁니다. 그러지 않으면
  1석짜리 대기가 여러 열차에 흩어져 짝이 영영 맞지 않습니다.
- `--max-standby` 로 동시에 걸어둘 대기 좌석 수를 제한합니다(기본 2 = 한 열차분,
  0=무제한). 좌석 상한(`--max-holds`)과는 별도로 셉니다.
- 열차의 대기 한도가 차서 거부되면(`예약대기자한도수초과` 등) 그 열차의 대기 신청은
  접습니다. 재시도해봐야 거부만 쌓이기 때문입니다.

> [!IMPORTANT]
> **예약대기는 결제되지 않으며, 배정돼도 스크립트가 대신 결제해 주지 않습니다.**
> 대기가 풀려 좌석이 배정되면 구입기한이 생기는데, 그 시점에 직접 결제해야 합니다.
> 즉 예약대기는 "걸어두고 사람이 확인하는 보험"이지 완전 자동이 아닙니다.

| 옵션 | 설명 |
| --- | --- |
| `--dep` (복수) / `--arr` | 출발역들 / 도착역 |
| `--prefer-dep` | 최종적으로 노릴 출발역 |
| `--include-standby` | 매진이어도 예약대기가 열려 있으면 대기를 신청 |
| `--max-standby` | 동시에 걸어둘 대기 좌석 수 상한 (기본 2, 0=무제한) |
| `--seats` | 한 열차에 모아야 할 좌석 수 (기본 2) |
| `--max-holds` | 동시에 들고 있을 1인 예약 총 수의 상한 (기본 4, `0`=무제한) |
| `--pay` / `--no-pay` | 예약 즉시 등록 카드로 결제 (**기본 켜짐**) |
| `--telegram` / `--no-telegram` | 예약·결제 내역 텔레그램 전송 (**기본 켜짐**) |
| `--summary-interval` | 진행 상황 요약 전송 주기 (분, 기본 60, `0`=끔) |
| `--dry-run` | 예약 없이 무엇을 시도할지만 출력 |

밤새 돌려두는 용도라, `--summary-interval` 주기로 **아무 일이 없어도** 진행 상황을
텔레그램으로 보냅니다. `시도`·`확보`·`거부` 같은 집계는 **시작 이후 누적치**이므로,
조용한 밤에는 숫자가 그대로입니다. 지난 요약 이후 새로 생긴 것만 보려면 `이번 주기`
줄을 보세요. 아무 일도 없었으면 `← 변화 없음` 이 붙습니다. 살아 있는지 확인하려고 터미널을 들여다볼 필요가 없습니다.
`Ctrl+C` 로 중단할 때도 마지막 요약을 한 번 보냅니다.

```
📊 srtgo-pair 정기 요약 (09/23 03:12)
경과 3시간 12분 · 384회차 (+60)
대상 수서→포항 · 마지막 회차 4편 중 예매가능 0편
이번 주기: 시도 +0, 확보 +0석  ← 변화 없음
누적: 시도 3회 → 확보 2석 (96,600원)
거부 사유(누적): 잔여석없음 1회
현재 보유: 277 2석
바닥 확보됨: 277 (이제 수서 만 탐색)
```

> [!WARNING]
> 기본값이 **자동 결제**입니다. 새벽에 잡힌 예약이 구입기한을 넘겨 사라지는 것을
> 막기 위한 것이지만, **짝이 맞지 않고 남은 1장짜리 표도 그대로 결제됩니다.**
> 목표 달성 후 남은 표는 `srtgo` 의 `예매 확인/결제/취소` 에서 직접 정리해야 하고,
> 이때 환불 수수료가 붙습니다. 지출 상한은 `--max-holds` 로 조절하세요.

> [!NOTE]
> 결제한 표는 예약 목록이 아니라 승차권 목록으로 옮겨갑니다. 이 명령은 양쪽을 모두
> 읽어 보유 좌석을 세므로, 방금 결제한 자리를 또 사는 일은 없습니다.
